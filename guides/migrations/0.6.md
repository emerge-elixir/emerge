# Migrate from Emerge 0.5.x to 0.6.0

The breaking change is the **message shape of six element pointer events**. They
now include an element-local position. Most applications only need to update a
few handler patterns or a shared payload adapter. Configuration, UI construction
and handlers using `Event.on_press/1` do not need a migration.

These changes are currently unreleased. The dependency constraint below is for
the published 0.6.0 release; use your Git/path dependency when testing the checkout.

## 1. Update the dependency

When 0.6.0 is available, update `mix.exs`:

```elixir
{:emerge, "~> 0.6.0"}
```

Then run:

```sh
mix deps.update emerge
```

If upgrading from 0.4, apply the [0.5 migration guide](0.5.md) first.

## 2. Accept pointer position payloads

Registration signatures stay the same. These helpers now deliver a
`%{x: float(), y: float()}` payload through the viewport's `wrap_payload/3`:

- `Event.on_click/1`
- `Event.on_mouse_down/1`
- `Event.on_mouse_up/1`
- `Event.on_mouse_move/1`
- `Event.on_mouse_enter/1`
- `Event.on_mouse_leave/1`

There is no opt-in flag or second, payload-free delivery. With the default wrapper,
a non-tuple stored message becomes `{message, position}`; a tuple stored message
has the position appended as its last field.

For example, keep these registrations unchanged:

```elixir
Event.on_click(:clicked)
Event.on_mouse_move({self(), {:pointer, :pad}})
```

**0.5.x handlers:**

```elixir
def handle_info(:clicked, state) do
  {:noreply, Map.update!(state, :clicks, &(&1 + 1))}
end

def handle_info({:pointer, :pad}, state) do
  {:noreply, Map.put(state, :pointer, :moved)}
end
```

**0.6.0 handlers:**

```elixir
def handle_info({:clicked, _position}, state) do
  {:noreply, Map.update!(state, :clicks, &(&1 + 1))}
end

def handle_info({:pointer, :pad, %{x: x, y: y}}, state) do
  {:noreply, Map.put(state, :pointer, {x, y})}
end
```

Use `_position` if you do not need coordinates. Messages targeting another PID
follow the same wrapping rules: update the receiving process too.

If you consume element notifications directly through `EmergeSkia.set_input_target/2`,
update the native envelope patterns as well:

```elixir
# 0.5.x
{:emerge_skia_event, {element_id, :mouse_move}}

# 0.6.0
{:emerge_skia_event, {element_id, :mouse_move, %{x: x, y: y}}}
```

This does not change raw pointer observer messages.

## 3. Check custom payload adapters

Custom `wrap_payload/3` callbacks receive the position map and the existing event
kind, such as `:mouse_move` or `:click`. Do not discard the map or assume that
these events still arrive without a payload.

An integration with a single payload slot may need to combine its fixed argument
with the new position. For example, a Solve-style route storing
`{:solve_event, event, argument}` can use:

```elixir
def wrap_payload({:solve_event, event, argument}, position, kind)
    when kind in [:click, :mouse_down, :mouse_up, :mouse_move, :mouse_enter, :mouse_leave, :drag] do
  {:solve_event, event, {argument, position}}
end

def wrap_payload(message, payload, kind) do
  Emerge.Runtime.Viewport.default_wrap_payload(message, payload, kind)
end
```

Its controller then accepts `{argument, position}` as one payload, for example
`{:pad, %{x: 35.5, y: 20.0}}`. Routes without a fixed argument can keep the default
wrapper. The `:drag` case supports the optional new drag helper described below;
it is not required for ordinary mouse events.

## 4. Use logical coordinates directly

- The origin is the receiving element's **outer top-left**, including its border
  and padding area, not the content's origin or the window's origin.
- Values are always floats, including at scale 1. Display scaling, inherited/local
  layout or paint scaling, rotation, translation and ancestor scrolling are undone.
- At effective scale 2, 71 physical pixels from the displayed left edge is
  `x: 35.5`. Do **not** divide by scale again, including fractional scales such as 1.6.
- Positions are not clamped. A leave sample can be negative or exceed the logical
  width/height. Window leave uses the last known pointer position because the
  backend does not provide an exit position.
- Down uses the press position; up and click use the release position. Each event
  is relative to its own listener element. `on_mouse_up` still targets the element
  under the release; it does not capture the element originally pressed.

### Optional: capture dragging outside a control

`Event.on_drag/1` is additive, not a required handler migration. Use it for a custom
control that must continue receiving movement and release outside its bounds:

```elixir
el([width(px(180)), height(px(120)), Event.on_drag(:picked)], none())

# Delivered using the default wrapper:
{:picked, %{phase: :move, x: 35.5, y: 130.25}}
```

Phases are `:start`, `:move`, `:end` and `:cancel`. Window leave or focus loss
cancels capture. Keep raw coordinates for inspection and clamp only application
values such as saturation. Ordinary mouse handlers do not capture or bubble.
Do not combine `on_drag` on the same element with click/press, swipe or virtual-key
handlers, or attach it to native text inputs/sliders. See `Emerge.UI.Event.on_drag/1`
for the full lifecycle.

## 5. Update native binaries and restart

Use the NIF and, on macOS, the host binary from the **same Emerge release**.
A normal supported release upgrade downloads matching precompiled artifacts;
older macOS hosts without the new payload protocol are rejected. Applications
that vendor native binaries must update those copies too.

For a Git/path checkout, rebuild native code instead of reusing a release binary.
Source builds require Rustler in the consuming application's dependencies:

```elixir
{:rustler, "~> 0.38.0", runtime: false}
```

```sh
EMERGE_SKIA_BUILD=true mix deps.compile emerge --force
```

When using a local macOS host, also set `EMERGE_SKIA_MACOS_HOST_BUILD_LOCAL=true`
when starting the application so that the window host is rebuilt from source.
See [viewport configuration](https://hexdocs.pm/emerge/Emerge.html#module-viewport-configuration)
for platform build settings.

Restart the application/BEAM after updating native code. Hot reload is not enough
to replace the loaded NIF or a running macOS host.

## What stays unchanged

- `Event.on_press/1`, including its payload-free pointer and keyboard activation.
  It remains the recommended helper for ordinary button actions. Do not replace
  pointer-only `on_click` handlers blindly: `on_press` also supports keyboard activation.
- Keyboard, focus/blur, text/slider change, swipe and scroll payloads.
- Raw `handle_input/2` subscriptions, message shapes and backend surface coordinates.
- `Emerge.Config`, layout/styling APIs and the generic default payload wrapper.

No raw input subscription is needed for element-local mouse events.

## Migration checklist

- Update patterns for all six changed events, including external recipients.
- Check fixed-argument adapters and custom `wrap_payload/3` callbacks.
- Update synthesized test messages and assertions to include float position maps.
- Exercise click/down/up/move/enter/leave and any custom dragging in tests.
- Install matching native binaries and restart the application.

Old patterns can still **compile successfully**. An unmatched message can crash a
receiver or be silently ignored by a catch-all, so compilation alone does not
validate this migration.
