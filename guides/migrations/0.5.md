# Migrate to Emerge 0.5

Emerge 0.5 replaces renderer keyword configuration with `%Emerge.Config{}`, adds
previous-config callbacks, and makes raw input observation explicit and typed.
This is a **breaking change**, with no conversion layer or deprecated aliases for
the replaced APIs. This guide describes the 0.5 release target; the branch's package
version remains 0.4.2 until release work is complete.

If upgrading from 0.3, apply the [historical 0.4 migration](0.4.md) first, then
this guide. UI tree construction, element-event messages and video atom targets
are not replaced by the config overhaul.

## Upgrade checklist

1. Return `%Emerge.Config{}` from every viewport `mount/1`.
2. Replace flat renderer startup with `EmergeSkia.start(%Emerge.Config{})`.
3. Remove `emerge_skia: [...]` and `viewport: [...]`; map their fields below.
4. Subscribe with `input.events` and update raw callback tuple names/actions.
5. Use a config callback for supported live settings, preserving previous records
   with typed updates instead of deep-merging keywords.
6. Update custom adapters to typed startup and full-snapshot `configure/3`.
7. Rebuild matching native artifacts/host binaries and cold-restart the BEAM when
   changing native code; do not hot-load over live or quarantined GPU resources.

Compile-time `config :emerge, compiled_backends: ...`, application `mount/1`
arguments and GenServer process options remain separate from runtime config.
Capture still reads a retained renderer as introduced in 0.4; it does not become a
one-shot tree API again. Headless frames still use `%VideoInterop.Frame{}`.

## Viewport mount returns

Before, renderer options could be merged directly into mount arguments:

```elixir
# 0.4 — removed
@impl Viewport
def mount(opts) do
  {:ok, %{count: 0}, Keyword.merge([title: "Counter", width: 800, height: 600], opts)}
end
```

After, interpret your application arguments and return a complete typed record:

```elixir
# 0.5
@impl Viewport
def mount(opts) do
  output = %Emerge.Config.Window{
    title: Keyword.get(opts, :title, "Counter"),
    size: Keyword.get(opts, :size, {800, 600})
  }

  {:ok, %{count: 0}, %Emerge.Config{output: output}}
end
```

Stateful viewports return `{:ok, state, config}` and render with `render/1`;
stateless viewports return `{:ok, config}` and render with `render/0`. State is a
map; `:__emerge__` is reserved. `{:stop, reason}` remains valid. Application start
arguments are still keywords, but are no longer automatically renderer settings.
For this example, change `start_link(width: 1024, height: 768)` to
`start_link(size: {1024, 768})` because that is what its new mount callback reads.

## Standalone renderer startup

```elixir
# 0.4 — removed
{:ok, renderer} = EmergeSkia.start(otp_app: :my_app, title: "Preview", rendering_api: :raster)
```

```elixir
# 0.5
{:ok, renderer} = EmergeSkia.start(%Emerge.Config{
  output: %Emerge.Config.Window{title: "Preview"},
  renderer: [api: :raster],
  assets: [otp_app: :my_app]
})
```

Only `start/1` with a root config is supported. Legacy keyword and positional
startup arities are removed. A viewport infers `assets.otp_app` from its module
where possible; a standalone caller must supply it. `owner` and baseline handles
are not user config fields: viewport ownership is internal, and standalone callers
must stop their own renderers.

`EmergeSkia.drm_outputs(drm_card: path)` remains a keyword **discovery query**.
Capture options, internal offline tree-rendering options, asset sigil options and
build configuration are separate APIs, not old renderer-start configurations.

## Map the old options

Paths below are fields inside `%Emerge.Config{}`. Fixed-shape records accept typed
keyword shorthand; `output` and `Headless.frames` variants require explicit structs.

| 0.4 option | 0.5 location / action |
|---|---|
| `backend: :wayland | :macos` | `%Emerge.Config.Window{backend: ...}` in `output` |
| `backend: :drm` | `%Emerge.Config.DRM{}` in `output` |
| `backend: :headless` | `%Emerge.Config.Headless{}` in `output` |
| `title`, `always_on_top` | `Window.title`, `Window.always_on_top` |
| `width`, `height` | `Window.size` or `Headless.size`; `DRM.preferred_size` is only a mode-selection hint |
| `drm_card`, `drm_output`, `drm_mode` | `DRM.card`, `DRM.connector`, `DRM.mode` |
| `rendering_api` | `renderer.api` |
| `backend_renderer`, `:gl` alias | Remove aliases; use `renderer.api: :opengl` |
| `[raster: [present: ...]]` or `[auto: [raster: [present: ...]]]` | `renderer.api: :raster | :auto`, `renderer.raster_present: :auto | :cpu | :gpu_upload` |
| `vulkan_drm_node` | `renderer.device`, independently of `DRM.card` |
| `headless.target_fps` | `renderer.target_fps` (supported on headless/Wayland, not DRM/macOS) |
| `renderer_cache.enabled` | `renderer.cache.enabled`; default `:auto` preserves API-dependent policy |
| `renderer_cache.max_new_payloads_per_frame` | `renderer.cache.max_new_payloads_per_frame` |
| `renderer_cache.paint_layer.*` | `renderer.cache.paint_layer.*` (`Emerge.Config.PaintLayerCache`) |
| `otp_app` | `assets.otp_app` |
| `assets.fonts`, `decode_at_size`, `runtime_paths.*`, `cache.*` | Same names under the typed `assets` record; font entries accept `Emerge.Config.Font` or typed shorthand |
| `viewport.input_mask` | `input.events`, an atom list; see raw input below |
| `scroll_line_pixels` | `input.scroll_line_pixels` |
| `hw_cursor` | `input.cursor.hardware` |
| `drm_cursor.default | text | pointer` | `input.cursor.default | text | pointer`, each a `CursorIcon` record or typed shorthand with `source`/`hotspot` |
| `input_log`, `render_log`, `close_signal_log` | Include `:input`, `:render`, `:close` in `diagnostics.logs` respectively |
| `renderer_stats_log`, `renderer_animation_log` | Include `:stats`, `:animation` in `diagnostics.logs` respectively |
| `stats` | `diagnostics.stats` |
| `drm_force_gpu_finish` | `diagnostics.force_gpu_finish`; diagnostic DRM EGL waits, not production synchronization |
| `drm_startup_retries`, `drm_retry_interval_ms` | `runtime.startup_retries`, `runtime.retry_interval_ms` |
| `viewport.renderer_check_interval_ms` | `runtime.health_check_interval_ms` |
| `viewport.renderer_module`, `viewport.renderer_opts` | `runtime.adapter`, `runtime.adapter_opts` |
| `headless.target`, `headless.frame_message` | `Headless.target`, `Headless.frame_message` |
| `headless.mode: :binary`, `pixel_format`, `bw1_polarity`, `dither` | `Headless.frames: %Emerge.Config.BinaryFrames{...}`; remove the mode flag |
| `headless.mode: :prime`, `prime.drm_node`, `max_in_flight`, `on_backpressure` | `Headless.frames: %Emerge.Config.PrimeFrames{device: ..., ...}`; remove the mode flag |
| `emerge_skia`, `viewport` namespaces | Remove them entirely; no nested-over-top-level precedence remains |
| `owner` | No public config equivalent; lifecycle-owned |
| `name`, `timeout`, `debug`, `spawn_opt`, `hibernate_after` | Remain GenServer startup options, not config fields |

See [viewport configuration](../reference/viewport-configuration.md) and each
record's module docs for defaults, validation and backend requirements. Not every
field represented by the schema is supported live or on every backend.

## Raw input

Raw `handle_input/2` observation now defaults to **no subscriptions**. Applications
that relied on the old default/mask behavior must declare what they observe:

```elixir
%Emerge.Config{input: [events: [:key, :text, :pointer_button, :resize]]}
```

Use `Emerge.Config.Input.all_events/0` for all eight categories, or `[]` for none.
Public numeric mask helpers/setters are removed. `events` rejects integers, `nil`,
unknown atoms and `:all`/`:none`; duplicates and order do not affect the set.
Subscriptions are live replacement, not additive. They filter only raw observers:
buttons, key bindings, text editing, scrolling and `handle_close/2` still work.

Update the **first argument of the viewport callback**:

| Old viewport value | New viewport value |
|---|---|
| `{:key, {key, 1, modifiers}}` | `{:key, {key, :press, modifiers}}` |
| `{:key, {key, 0, modifiers}}` | `{:key, {key, :release, modifiers}}` |
| `{:cursor_pos, {x, y}}` | `{:pointer_move, {x, y}}` |
| `{:cursor_button, {button, action, modifiers, position}}` | `{:pointer_button, {button, :press \| :release, modifiers, position}}` |
| `{:cursor_scroll, {delta, position}}` | `{:pointer_scroll, {delta, position}}` |
| `{:cursor_entered, entered?}` | `{:pointer_enter, entered?}` |
| `{:resized, {width, height, scale}}` | `{:resize, {width, height, scale}}` |
| `{:focused, focused?}` | `{:focus, focused?}` |
| Text commit/preedit/clear/deletion values | Same text operation names, under the `:text` subscription |

Keys remain canonical key identifiers; text commits/IME are not key presses.
Repeat is `:press`. Low-level `EmergeSkia.set_input_target/2` messages retain their
native event envelope/names and numeric actions; do not apply this table to a
standalone target process. The viewport converts that boundary to `Emerge.Input`.
Headless has no physical input, DRM has no desktop enter/focus lifecycle, and IME
availability varies. See the [input guide](../tutorials/handle_input.md).

## Declarative live configuration

There was no previous-config callback to preserve. In 0.5 implement at most one
of `config(previous)` and `config(previous, state)`, or neither for mount-only config.

```elixir
@impl Viewport
def config(%Emerge.Config{output: %Emerge.Config.Window{} = output} = previous, state) do
  output = %Emerge.Config.Window{output | title: state.title}
  %Emerge.Config{previous | output: output}
end
```

The callback runs before initial renderer creation and during coalesced rerenders,
including config-only updates and while a DRM display is off. The first argument
is the latest **normalized desired config** with nested structs, not readback or
last accepted/applied state. Return a complete root record; there is no implicit
merge with mount config. Use typed updates to preserve values, one record at a time.

For example, do not replace an explicit backlight binding with
`backlight: [brightness: new_level]` expecting its path to survive. That shorthand
rebuilds a record from defaults. Instead:

```elixir
backlight = %Emerge.Config.Backlight{previous.output.backlight | brightness: new_level}
output = %Emerge.Config.DRM{previous.output | backlight: backlight}
%Emerge.Config{previous | output: output}
```

Lists (events, fonts, logs, allowlists) also replace rather than append. Callback/
schema/capability failures preserve previous intent. Operational failures preserve
new desired intent for retry/recovery; accepted is not applied and applied is not
a rollback guarantee. `EmergeSkia.config_status/1` exposes native session/revision
progress; macOS host revision reporting is not implemented.

### Current supported changes

- Live: raw subscriptions, health interval, Wayland/macOS titles,
  headless/Wayland frame caps, and DRM display/brightness with explicit OpenGL or CPU raster.
- Rejected live: DRM connector/mode changes and DRM/macOS frame caps.
- Startup-only: output type/card, drawing API/device, size/hint, cursor, assets,
  diagnostics and custom adapter identity/options; create a new viewport.

Caps limit drawing, not physical refresh or application timers. `nil` restores
backend pacing. The known Wayland Vulkan acquire synchronization defect remains
separately deferred; the schema does not imply validation qualification.

## DRM power and brightness

These are new declarations, not compatibility wrappers around app-side sysfs writes:

```elixir
%Emerge.Config{
  output: %Emerge.Config.DRM{
    connector: "DSI-1",
    display: :off,
    backlight: [device: "/sys/class/backlight/panel", brightness: 0.5]
  },
  renderer: [api: :opengl]
}
```

Use your actual backlight path. Explicit OpenGL or raster `:auto | :cpu` presentation
supports controls; Vulkan, raster GPU upload and unspecified `api: :auto` remain
guarded. Auto backlight selection requires proven association, `nil` opts out,
brightness is finite `0..1`, zero is not off, and nil restores the original requested
level retained across recovery.

Off keeps ownership/tree/intent, ignores native UI input, defers routine viewport
render/upload and destroys presenter resources. Initially-off still acquires the
owner. On creates a fresh presenter from the latest tree and enables a managed
backlight after first application presentation. There is no GPU state restoration,
strict config/frame provenance or physical no-flash guarantee. Applications own
independent wake sources; off does not suspend the OS or application timers.

## Diagnostics

Replace independent root logging booleans with a list under `diagnostics.logs`:

```elixir
%Emerge.Config{diagnostics: [logs: [:stats, :animation]]}
```

`stats: true` collects structured data for `EmergeSkia.stats/2` without periodic
stats output. `logs: [:stats]` enables collection **and** summaries, so specifying
both is unnecessary for logging. Logs and the native stats API share/reset one
measurement window. Renderer collection is startup-only; the stats API's
`{:configure, ...}` command is not supported for renderer handles. macOS supports
summaries but not that API. Other log categories do not enable collection.
`force_gpu_finish` adds blocking DRM EGL waits and distorts measurements; it is
not a synchronization fix. See `Emerge.Config.Diagnostics` for exact effects.

## Custom renderer adapters

There is no legacy adapter shim. Select your module and opaque options through
`runtime: [adapter: MyAdapter, adapter_opts: [...]]`.

The internal adapter behaviour is defined in
`lib/emerge/runtime/viewport/renderer.ex`. Update these contracts:

- `start(config, adapter_opts)` receives normalized `%Emerge.Config{}`, not flat
  renderer keywords. `adapter_opts` remains the explicit opaque keyword list.
- Implement required `configure(renderer, previous, desired)` for a **complete
  live snapshot**, including retries after partial failure and equal snapshots.
  `previous` is last accepted submission, not a hardware snapshot.
- Return `:ok` synchronously, `{:error, reason}`, or `{:pending, {session, revision}}`.
  Async completion is `{:emerge_skia_config, {session, revision}, :ok | {:error, reason}}`
  sent to the calling viewport. Tokens must be unique across sessions; stale replies
  cannot acknowledge a replacement renderer or newer revision.
- Keep `stop/1`, `running?/1`, target routing, `upload_tree/2`, `patch_tree/3`, and the
  optional `patch_tree_runtime/3` contracts. `set_input_mask/2` is an **internal
  adapter/transport callback**; the public observer API is `input.events`.
- Keep liveness heartbeats and safe resource ownership. Initially-off can bind
  targets before upload; do not require a tree upload to complete acquisition.

For the normal adapter, native title/cap/input/power work stays on its owner threads.
NIF admission is bounded and GPU/KMS waits do not hold configuration revision locks.
See [config reconciliation](https://github.com/emerge-elixir/emerge/blob/main/guides/internals/config-reconciliation.md).

## Build and deploy

Recompile the dependency after changing backend features or migrating native code:

```sh
mix deps.get
EMERGE_SKIA_BUILD=true mix deps.compile emerge --force
```

Source builds require an explicit Rustler dependency and a configured toolchain;
release artifacts must match the library/host protocol version. See
[Build the native renderer](../reference/native-renderer-builds.md). Stop producers
and renderers safely before replacement; pending/quarantined cleanup does not make
an output reusable. Hardware power timing and panel behavior require device tests,
separately from host compilation/tests. This guide does not assert that 0.5 has
been published or that device qualification has completed.
