# Changelog candidates: retained renderer vs main

This is a draft for release review, **not** the [product changelog](../../CHANGELOG.md).
Use **Added**, **Changed** or **Removed** for intentional public differences;
reserve `Unreleased → Fixed` for a reproduced `main` bug with an expected result
and a retained regression. A different implementation with the same result gets
a [decision](retained-decisions.md), not a release note. A limitation of this
branch stays in [API parity](../../plans/api-parity.md).

## Intentional changes

| Kind | Candidate release note | Decision / evidence |
| --- | --- | --- |
| Added | `wrapped_column/2` lays children out top to bottom, then starts a column to the right. Height fills share their column; `space_evenly()` distributes the remaining height within each column. Horizontal alignment uses that column's width. `width(content())` fits the occupied columns and gaps. Cards can wrap text at the single-column width before packing. A pack cannot use a height share that itself depends on the pack's width. | [D10](retained-decisions.md#d10-wrap-columns-at-the-resolved-height) · [one-pixel wrap and local click](../../test/emerge_skia/wrapped_column_test.exs) |
| Changed | `wrapped_row` now uses minimum widths to choose line breaks, then divides each line's available width by weight, respecting those minima. Two `fill()` children that used to occupy separate lines can now sit side by side. Pixel and content caps can keep a peer on the same line; a floor can push it to the next. Nested widths may combine several fill weights without counting the child twice: in an 84px row with a 4px gap, raising one cap can change a 40/40 split to 50/30 without moving either card to another line. This is intentional, **not a bug fix**. | [D7](retained-decisions.md#d7-share-fill-widths-per-wrapped-line) · [48/48, 24/72 and the wrap threshold](../../test/emerge_skia/wrapped_row_fill_test.exs) |
| Changed | `space_evenly()` on a pixel- or fill-width `wrapped_row/2` now distributes leftover width **within each line** instead of being ignored. Authored spacing still decides which children fit; a single child stays at the start. | [D12](retained-decisions.md#d12-distribute-even-gaps-after-sizing-each-linear-group) · [multi-line frames and clicks](../../test/emerge_skia/linear_even_spacing_test.exs) |
| Changed | A globally keyed element of the same kind keeps its occurrence across parent moves or promotion to root; removing it from an accepted declaration ends that lifetime. A press can survive a move, not a removal/reinsert. | [D2](retained-decisions.md#d2-identify-occurrences-rather-than-matching-subtrees) · [promotion](../../test/emerge_skia/viewport_constraints_test.exs) · [press across an aligned Row ↔ El move](../../test/emerge_skia/el_child_alignment_test.exs) |
| Changed | Low-level EMRG clients must use v10 declarations/patch terms; v9 bytes and opcode lists are not accepted. Call `upload_tree/2` on a vacant renderer, then use the returned state with `patch_tree/3` even for a new root. Pass `nil` to clear; `none()` mounts an element. | [D3](retained-decisions.md#d3-replace-one-target-instead-of-sending-a-list-of-mutations) · [wire contract](emrg-format.md) |
| Changed | If siblings from different alignment groups overlap, the later-declared sibling paints on top; the later eligible listener wins the click. Aligning a card right or bottom does not raise it above later siblings. This also applies to a stacked float overlapping a later paragraph in a [text column](../../plans/checkpoints/layout/text-column.md). | [D11 and reference pixel](retained-decisions.md#d11-place-alignment-groups-without-changing-stacking) · [overlap and reorder](../../test/emerge_skia/linear_zones_test.exs) |
| Changed | Menus on sibling hosts share a layer. A tooltip on either menu appears above both menus but below a scrim attached to their common ancestor. Reordering the siblings swaps the menu winner without moving their tooltips below a menu. | [D26](retained-decisions.md#d26-stack-nearby-by-layer-then-by-declaration-order) · [installed pixels and local clicks](../../test/emerge_skia/nearby_layers_test.exs) |
| Changed | On live binary headless and Wayland, native edit success means applied, not queued or displayed. A busy submission can be retried from the same accepted state. A ready frame may be handed off while a newer one is still drawing. | [Admission and installation](layout-refresh-render-flow.md#current-retained-path-binary-headless-and-wayland) · [stalled-stage controls](../../test/emerge_skia/stage_isolation_test.exs) |
| Changed | After a tree or callback edit, clicks still use the last successfully submitted pixels, listener geometry and route until the new frame is installed. Local coordinates themselves are **not** new to current `main`. | [D5](retained-decisions.md#d5-publish-input-with-the-successful-submission) · [pending edit and click](../../test/emerge_skia/retained_tree_slice_test.exs) |
| Changed | A clickable inline phrase in `paragraph/2` receives clicks on each visible continuation. Gaps remain with the paragraph or the content behind it. Coordinates are relative to the same element across lines, not reset at the start of each line. | [D14: observed before/after on a Wayland seat](retained-decisions.md#d14-break-paragraph-lines-once-and-submit-their-hit-regions-with-the-ink) · [continuation, gap and held click](../../test/emerge_skia/paragraph_flow_test.exs) |
| Changed | A single translucent PNG is blended directly. Antialiased rounded-edge pixels can round differently than with an intermediate opacity layer (one channel level in the raster controls). An overlapping background and image still receive opacity as a group. An undersized, undecorated `el` does not crop overflowing media; outer linear clips still apply. | [D16 and raster comparison](retained-decisions.md#d16-apply-image-opacity-at-the-compositing-boundary) · [host and clip controls](../../plans/checkpoints/layout/raster-images.md) |
| Changed | With `assets.decode_at_size: true`, visible uses of one PNG or JPEG share a bitmap sized for the largest fitted draw. A smaller first draw on the same frame can sample like a warmed draw rather than a fresh thumbnail. Intrinsic layout is unchanged. | [D18](retained-decisions.md#d18-fit-decoded-memory-to-the-prepared-drawing) · [memory and pixels](../../plans/checkpoints/layout/sized-rasters.md) |
| Added | Binary headless sessions accept raw pointer, key, focus and text-commit input via `EmergeSkia.send_input/2`; subscribers and element listeners use the normal dispatch path. | [D5](retained-decisions.md#d5-publish-input-with-the-successful-submission) |
| Added | `Config.Renderer.tree_headroom_percent` controls startup reservation for tree updates (default 80, range 0–1000). Oversized/deep declarations can be rejected without replacing the accepted tree. | [D4: bounds and scope](retained-decisions.md#d4-reserve-before-committing) |
| Removed | The low-level `EmergeSkia.Native.tree_node_count/1`, `tree_is_empty/1` and `tree_clear/1` bindings were removed. Use a stateful patch to clear. The separate test harness was not an application API. | [D5](retained-decisions.md#d5-publish-input-with-the-successful-submission) |
| Changed | Explicit Wayland GPU starts may fall back once to CPU shm on proven hardware unavailability, with a warning and an accurate requested/selected API report. This is not a silent switch after startup or a workaround for missing build features. | [D8](retained-decisions.md#d8-submit-the-same-retained-drawing-to-explicit-wayland-presenters) |
| Changed | On supported sessions, accepted title, input-mask and frame-cap revisions can be reported applied immediately. Configuration completion still does not acknowledge a new frame. | [D9](retained-decisions.md#d9-apply-supported-live-controls-directly) |
| Removed | `{:id, id}` is no longer an image source. Reuse the original file source, or pass encoded bytes with `binary/1` to `image/2` or `svg/2`. Image backgrounds take file sources only. | [D21](retained-decisions.md#d21-declare-artwork-by-source-not-cache-id) |
| Added | `image/2` and file backgrounds can display still WebP (lossless, lossy and alpha), including EXIF-oriented images. Animated WebP is not supported. | [D24 and decoded references](retained-decisions.md#d24-decode-still-webp-on-the-existing-raster-worker) |
| Added | `path/1` and `binary/1` declare a file or encoded bytes for `image/2` and `svg/2`. Enabling absolute files still requires an explicit runtime-path policy. | [Source examples](../tutorials/use_assets.md#choose-a-file-or-pass-bytes) |
| Changed | Static, self-contained SVGs use one vector picture per resident source per renderer instead of cached pixels per size. `svg_tree_max_entries` and `svg_tree_max_bytes` now budget idle pictures; supported SVG text uses bundled fonts. PNG/JPEG fitted decoding is unchanged. | [D20](retained-decisions.md#d20-share-one-skia-picture-per-svg-source-on-every-renderer) · [pixel and source tests](../../test/emerge_skia/svg_pictures_test.exs) |
| Changed | Native source builds resolve `skia-safe` 0.157.0 from the Cargo registry. The SVG frontend uses `usvg` and the AnyRender Skia painter, without a second Skia or a GPU requirement for raster builds. | [Native renderer builds](../reference/native-renderer-builds.md) |

## Verified fix candidates

Porting [Image transforms, height-driven width, BMP/GIF and file backgrounds](../../plans/images-and-svg.md) and [bounded Image sizing, width from an allocated height and indexed BMP](../../plans/image-sizing-and-codecs.md) restores behavior observed on `main`; these are not new public APIs. The image-turn fix below was reproduced on `aef5e42f`. [Static layout rotation and transforms that preserve sibling layout](../../plans/static-layout-transforms.md) also use existing helpers. [Paragraph inline layout rotation](../../plans/inline-layout-rotation.md) deliberately corrects `main`: both rotation helpers visibly turn the phrase and its click target, but only `UI.rotate/1` reserves the rotated footprint when placing following text. Inline peers now honor `align_top/0`, `center_y/0` and `align_bottom/0` within that line's occupied height; a wrapped peer aligns separately on its next line. Neither port adds an API or animation support. The [static Size work](../../plans/size.md) restores height-driven widths at document blocks and floats, nested shares and independently measured Row charges. These are not new length forms. Retained's existing outer-box line advance also applies to empty fixed-height header cards: at width 120 the two 75×20 cards take 40px, not the overlapping 20px on pinned `main`. [Reference differences](../../plans/size.md#reference-differences).

**Which `main`?** The before measurements for the original layout regressions ran on pinned Emerge
`5c71a593acfcbb2675c3bd282c680633439e7745`. The API reference is current local
`main` at `aef5e42fc789c396505f85c34810b2ca9c008586`: source comparison of
`tree/layout.rs` and `tree/layout/` shows only the added `on_drag` field copy,
not a change to these sizing rules. This is **not** a new run of that revision.
Pinned clicks are not an oracle for local payloads; those controls used the
pre-cut `5b389e7f` **with its overlay**. The linked regressions run against the
retained renderer. Keep or refresh the before evidence if `main` moves.

Separately reproduced on `aef5e42fc789c396505f85c34810b2ca9c008586`:
**preserve the gap after a fill-height child on a wrapped line**. In a 48×64
host with padding 2 and gap 4, raising A's cap from 16px to 32px left the next
line at y=18 in both frames and overlapped A. The next line now starts at
**y=22 then y=38**, four pixels below A's box. [Submitted cap edit, undo and
click targets](../../test/emerge_skia/wrapped_row_height_test.exs).

Also reproduced on `aef5e42f`: in a 64×64 WrappedRow with padding 4 and
16×16 and 32×32 siblings, `align_bottom()` on the first should put it at
**y=20**. Only a 16×4 strip was visible at y=0 on `main`; retained draws the
full 16×16 box at y=20. Ordinary Row/Column center controls matched `main`.
[Line alignment regression](../../test/emerge_skia/wrapped_column_test.exs).

**Keep visible solid backgrounds on unbounded document blocks.** On `aef5e42f`,
`height(fill())` on a non-floating TextColumn block receives an effectively
unbounded height. Its solid background could disappear from the viewport even
though the block was there. Retained paints the visible portion, matching a
400px-tall control in a 196px viewport, without changing the height offer or
pulling the following block back on screen. [Public fill/cap/undo and click](../../test/emerge_skia/text_column_test.exs) ·
[matched geometry, raster and Skia control](../../plans/checkpoints/layout/text-column.md).

**Display JPEGs whose EXIF orientation swaps width and height.** On `aef5e42f` a non-square 16×8 JPEG with orientation 6 showed the failed-image indicator at full-resolution decode. It now displays as 8×16; intrinsic sizing and contain/cover use the upright picture. All eight EXIF origins matched independently oriented pixel controls. [D17](retained-decisions.md#d17-bind-jpeg-pixels-in-display-orientation) · [JPEG regression and reference](../../plans/checkpoints/layout/jpeg.md).

A retained refusal before a port, or a clipping correction that restores
`main`'s pixels, is not evidence for a `main` fix. No candidate above has been
promoted by this documentation change.
