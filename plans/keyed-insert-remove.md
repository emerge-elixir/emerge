# Keyed child insertion and removal

**Implemented on the ordinary binary CPU headless renderer.** Removing B from P’s child list does not require freeing B’s slot. In `[A, C] → [A, B, C] → [A, C]`, C stays mounted as it moves; B can stay cached while detached.

## Patch cycle: apply all → invalidate once → recompute

Apply every patch queued for this cycle in order. Each patch sees the preceding patch’s edits. During mutation, record touched keys, edited parents and attachment changes in reserved scratch; leave the computation worksets empty. Patches arriving after the invalidation pass starts belong to the next cycle.

1. **Build the replacement child list for each edited parent.** Use the existing `insert_subtree` (tag 3), `remove` (4), `SetAttrs` and same-parent `SetChildren`. Replay commands in order in reserved scratch. Keep `moved` for children displaced from an old list and `seen` for children present in its replacement, including survivors not named by an insert. Look up keys without distinguishing who supplied them; allocate on a miss. `moved − seen` are detached subtree roots, not a list of slots to free. Untouched parents are not part of this comparison.
2. **Validate and reserve before committing.** Reuse the upload proof for inserted subtrees. Preserve append for oversized indices and redundant descendant removes. Check even shadowed records, attached-ID collisions, parentage, final arity, byte/node/depth limits and capacity. A rejected batch contributes nothing to the cycle; preserve earlier accepted edits, their scratch and installed output. Commit one authoritative child order. No root replacement, reparenting, Nearby, exit animations, new NIF or full-upload fallback.
3. **Invalidate once, after the last patch and before any recompute.** Walk the accumulated changes against the final child lists and last computed inputs. A child seen in an early patch but detached by the last one gets no work; a parent losing its last child still needs checking. Seed each affected `(pass, key)` once, merging paint/hit requests. Then recompute in dependency order: compare offers and offsets even if P’s frame is unchanged, and invalidate downstream readers only when their input changes. No per-patch invalidation pass, forced draw or per-slot queue unlinking.
4. **Reuse computed values, not an old attachment.** A detached subtree is absent from the next layout, paint, hits and encoded node count; its storage still counts against headroom. Keep it while it fits; reclaim detached storage under pressure rather than on every remove. On a matching key and shape, compare with the inputs **last computed**: B can reuse its glyphs if its text and effective font still match, even if it needs a new position or clip. Keep hit identity tied to the attachment, not to the cache slot: a new attachment never inherits an old press. Install hits only on a successful draw, including pixel reuse.

**Which key returns?** EMRG v9 carries numeric IDs, not DSL keys. Today Elixir [explicitly tests](../test/emerge/diff_state_test.exs#L396) that removing and later reinserting `key(:b)` gives it a **fresh ID**. Keep that contract for now: Rust can reuse storage, but lookup by that new ID cannot find B’s old computed values. The native test verifies a warm hit when the incoming ID repeats. If ordinary DSL reinsertion must guarantee that hit, decide how Elixir supplies stable cache identity; don’t guess from equal attributes.

## Acceptance

- Freeze pre-cut roundtrips, geometry, delivered frames and raw input first. On one 80×20 viewport use a gapless row: A red 20px, B green 20px, C blue 40px. Consume each frame. At `(25,5)` clicks go C → B → C, all local `(5,5)`; at `(65,5)` miss → C → miss. Press C at `(45,5)`, insert B, then release there: C still clicks, now local `(5,5)`. Press B across removal and reinsertion: no click until a fresh press/release. Check pixels and both viewport callbacks; a pending edit must not retarget the installed frame.
- Start from a drawn `[A, C]`. Queue three patches before one recompute: insert B, change C’s color, remove B. Verify no workset entries during mutation, one invalidation pass after all three, no recompute for B, and C painted in its new color without remeasurement. Restoring the original child order must not discard C’s independent edit.
- Keep the eight ordinary [patch regressions](../test/emerge/patch_test.exs#L184) unchanged. Compare incremental and cold output. Exercise a repeated wire ID with unchanged inputs, changed inherited inputs, and an edit still pending when detached. Check survivor keys, absent descendants, no unrelated remeasure, identical pixels with a fresh hit identity, and bounded storage under churn through fresh IDs.
- Check atomic rejection and `[0,0,0]` alloc/realloc/free for fitting edits from wire decode through paint/hit inputs; isolate necessary growth. Rerun Row/first-slice controls, release Cargo tests/build, strict Clippy and focused/full Mix under the shared lock with the mapped NIF verified. Compare named failures against the depth-workset checkpoint (104 failed, 21 excluded).

## Results

- In [`wire/batch.rs`](../native/emerge_skia/src/tree/wire/batch.rs) each batch sees the accepted declaration state. [`changes.rs`](../native/emerge_skia/src/tree/changes.rs) saves the first replaced input per touched slot until refresh. Insert B → recolor C → remove B left all seven worksets empty during mutation; the single invalidation pass led to paint composition for C and its parent only. Repeated wire IDs reused unchanged glyphs, not an old press. A rejected batch preserved earlier work. No raw patch queue, extra renderer or wire-format change.
- The six frozen states matched the pre-cut retained overlay: **6 roundtrips, 6 geometry dumps, 6 whole delivered RGBA buffers and 18 raw click probes**. Previous Row/clip and first-slice controls matched too. The eight existing patch regressions and the new moving-sibling viewport test passed unchanged on both producers.
- A separate capped viewport exposed an intentional difference. While B's pixels were still displayed after removal was submitted, the pre-cut selected C; the intermediate implementation lost B's callback. Now the same session lock orders sparse callback-address changes, their installation after a successful draw, and native input to the viewport relay. Elixir keeps the drawn and pending routes; the renderer stores no callback term. The capped viewport calls B before the draw and C afterward. A callback-only pair of edits installs only the final address even with identical pixels. No public frame selector, version token or new NIF entry point.
- **35 release Rust tests**, release build, strict Clippy and formatting passed; the private mapped NIF matched Cargo (`b402891fb36934f5f165508b1b83c0f3c8110821fa3f969c59b9db83de74d720`). A 100-node upload fit 180 resident nodes, including the first insert, removal, reattachment and back-to-back edits, with **[0,0,0]** alloc/realloc/free from wire decode through recompute and paint/hit inputs. Slot 181 required growth; its first recompute again used zero calls. This does not include rasterization or BEAM delivery and is not a timing result.
- Focused renderer/patch checks: **19 passed**; loader **14 passed**; extended migration sweep **33/56**, unchanged. Full private Mix: **636/732 passed** (15/15 doctests, 621/717 tests), **96 failed, 21 excluded**. The eight named patch regressions are no longer failing; no new failing names or exclusions. Credo and Dialyzer passed. Root replacement by patch, live reparenting and Nearby remain out of scope.
