# Compile hit regions; share the listener, not the target

**Implementation proposal, not implemented.** A hit entry is **`(region, hit_listener)`**. The region answers *where*; the listener describes *what to do with the match*. Applying the shared rule to the matched member and input can consume silently, emit ordered actions, or split dispatch into named passes. A hit is not itself an application event. Neither the region nor the listener needs a link back to the paint tree. This changes retained input storage on binary headless and Wayland, not the UI API, event messages, drawing order or scroll cache policy.

## What to replace

Today [`Hit`](../native/emerge_skia/src/tree/paint.rs) is 96 B on x86-64. A listener, a blocker and a child-program call all pay for the same fields: action bits, wheel link, paint scope, attachment, ID, rectangle, origin and scale. `Hits::at` and `Local::hit_with` interpret planes and clips while matching. The [Field Notes measurement](checkpoints/performance/field-notes-memory.md) found **594.54 MiB** of four-hit leaves and branches alone when reserved in isolation for the 20k page at 80% headroom. The bound uses 126,062 padded owners and seven possible versions, not the number of listeners. The real upload was refused **before** that allocation; the offline first view had 18 logical hits and used 17 hit leaves, no forks.

The candidate [Elixir callback registry](../lib/emerge/engine/event_registry.ex) is a different object: **25,010 click targets** (20,000 notes, 5,000 flags, 10 controls), **5.21 MiB** of sharing-aware BEAM heap terms, not RSS. No need to inspect, hash or intern application messages in Rust. The bound and registry count are reproducible from `/workspace/.notes-hit-count-oVAZng/RESULTS.md`.

## Matching contract

1. Use **one logical array in paint order**, read frontmost first. A pass sees its participating entries. `region.match(point)` returns `Miss` or a member (implicit for a single region). On the first match, bind the member to the listener and **stop that pass**, including when the result is “consume without emitting.” Missing a callback on the winner is not permission to hit the sibling underneath. Ordinary passive text has no entry; a listenerless escaping Nearby root *does* block inside its shape.
2. Choose a listener from a **small set of native rules**; don't allocate a closure per element. Rules are equal when their action bits, payload convention and pass behavior agree, regardless of element ID or Elixir message. Use the existing [`Actions(u16)`](../native/emerge_skia/src/tree/interaction.rs) for the capabilities it describes (`UP`/`DOWN` are **swipes**, not mouse or key edges). A tag identifies the shared rule. Do not force key matchers, soft-key specs or mutable gesture state into that mask. The varying operands are:

   | Rule | Context needed on a match |
   | --- | --- |
   | Consume | None. No target, coordinate map or message. |
   | Element action | A target slot resolving to the numeric ID and installed `(key, generation)` attachment. For a position-bearing action, derive coordinates from the recipient's **unclipped** origin and scale, or its prepared local-coordinate map if posed. Bare press/focus/blur need no coordinate payload. |
   | Scroll body / chrome | An installed port slot; axis and track/thumb role where applicable. Keep controller state and enclosing-port links once per port, not on each listener. A run can inherit its port slot. |

   For example, two rows can both use `Element(CLICK)`. Matching Note 17 supplies **its** target; a valid tap produces `{id_bin, :click, %{x: local_x, y: local_y}}` under the existing installed route epoch. Note 18 can send a completely different application message with the *same native rule*. No PID, BEAM term, environment or route epoch per rectangle. A down-match identifies a candidate; the existing [gesture dispatcher](../native/emerge_skia/src/session/dispatch/gesture.rs), not `contains`, decides when to emit.
3. Make pass participation explicit. A port body participates in scroll targeting without shielding an ordinary listener from a tap; a scrollbar consumes a press **on its track**, not across the port. A splitter names the subpass, where it starts and which result runs next. Delegating to the base rules skips the invoking splitter; an explicit continuation *below* a match starts after that member in the same installed order. Neither an empty action list nor an absent BEAM route implies continuation. Wheel components follow the winning region's installed port ancestry, never a covered sibling. Raw observation and offscreen Tab/reveal are not extra hit passes.

### Split listeners: one input is not one hit

Only a **point pass** searches the regions. Other steps already know their recipient: the previous hover owners, a captured attachment, the focused mount or a controller. Resolve those bindings directly. All steps of one split use the same installed frame and route epoch. Reuse a point result only if the point, participants and starting position agree; the move winner need not be the enter winner. A member with down, up and move on one shape needs one region, not three. Dispatch each action under its own event kind, wrapping only actual payloads.

The [public event contracts](../lib/emerge/ui/event.ex) and [reference splitters](../guides/internals/events.md#splitter-listeners) specify the following cases. Retained already supports click/press, drag, directional swipes, scroll and basic focus/navigation. Mouse lifecycle callbacks, custom keys, editors/sliders and virtual keys are [remaining ports](api-parity.md), **not features delivered by this storage change**.

- **Mouse motion and hover:** split a real move or an in-window left release as **leave → ordinary input → enter**. Window exit has no enter; leave uses the last known position. `on_mouse_move` is for real motion. `on_mouse_enter` and `on_mouse_leave` describe transitions: compare the prior hover owners with the new hover selection, retaining common ancestors. The enter winner identifies its interested ancestry, not every region underneath. In the [transformed child fixture](../test/emerge/mouse_coordinates_test.exs), one move at `(139,82)` gives child move and enter at `(35.5,20.25)` and parent enter at `(69.5,41)`. The child's move did not bubble. Revalidate hover on installed geometry changes without fabricating move, drag motion or raw input.
- **Mouse buttons and activation:** `on_mouse_down` and `on_mouse_up` are left-button, location-based listeners, not capture. On an ordinary press on A and release over B, up targets the release hit; neither gets a click just because one edge hit it. For a valid tap with all three handlers, run ordinary mouse up, then click at the release position, then payload-free `on_press`. A consumed pan or drag cannot also tap. Focused Enter activation is not a pointer hit or a custom `on_key_press`.
- **Captured gestures:** `on_drag` wins at press and starts immediately. Real motion and release use the source's *current installed* map even outside its region; emit `%{phase: phase, x: x, y: y}` with phase `:start`, `:move`, `:end` or `:cancel`. Window leave/focus loss cancels at the last position; losing the mount, handler or usable geometry drops capture without a terminal event or transfer. Capture owns its move/release step, not physical hover. Preserve the drag conflicts with click/press, swipe, virtual keys and native editor/slider drags. Directional swipes instead keep the press-local start and input time; a qualifying release supplies the current source-local end and elapsed milliseconds. Primary touch uses the gesture rules without generating raw mouse events.
- **Custom keys:** `on_key_down/2`, `on_key_up/2` and `on_key_press/2` match the **focused attachment**, not the pointer. Keep ordered bindings for canonical key, phase, modifiers, `:exact`/`:all` and opaque route ID. A matching down can emit down and arm a completed press; on matching release deliver up **before** the armed press. No press after focus/source loss or a release without a matching down. Preserve precedence with other bindings, Tab, focused activation and default editing, including suppression of a handled text commit. In [viewport routing](../lib/emerge/runtime/viewport.ex), interpret `{id, kind, route_id}` as a lookup by `{kind, route_id}` **before** generic three-field payload wrapping, including on the epoch-tagged path. Deliver the stored message unchanged.
- **Value, scroll and focus notifications:** `on_change` is an output of a native edit or slider value change, not a hit at the last pointer position. Route the new text binary or slider float to the owning mount. Editing still works without a callback; an app echo does not emit another change. The control may need a region for focus/selection or thumb acquisition, but `on_change` adds none. Likewise `on_scroll` emits changed port fractions, not local pointer coordinates; resolve each wheel axis separately and coalesce by changed port. `on_focus`/`on_blur` follow the focus transition and carry no payload. Hover/pressed/focused *styles* are native state changes, not extra application callbacks.
- **`virtual_key/1`:** the point hit arms the soft key's **action spec**, without taking focus. It cannot be combined with `on_click` or `on_press`. A valid tap feeds the normal key/text dispatch path: text → commit; key → down/up; text-and-key → down, commit, up with the specified modifiers. These intentional inputs retain normal key/text observation and editing rules; never redispatch the pointer sample as raw input. A hold either does nothing special, repeats the tap, or sends the soft key's bare `:virtual_key_hold` route. After a hold fires, release does not append a tap. Keep source and focused mount, phase and deadline per active pointer/contact, not per rectangle. Slide-off or cancel disarms; changing the key action or replacing the key or focused mount must not redirect a pending hold. Independent touch keys must not steal the primary gesture or each other's feedback.

## Implementation sequence

Build and compare these slices in tests. Switch the single production matcher only when the representation is both equivalent and funded; do not ship parallel banks or input paths.

1. **Freeze an oracle before changing representation.** On the current cut, record winners, blockers/misses, attachment, local payload, scroll port/axis and ordered messages for the same points and inputs. Use the existing point matcher as a test-only differential oracle plus hand-checked boundary cases. For not-yet-ported splitters, take ordered traces from pinned `main` (`aef5e42`, `events/registry_builder.rs` and `events/runtime{,/touch}.rs`) and the public fixtures; the retained decoder's refusal is not an event oracle. Distinguish a consumed pass, an emitted action and a scheduled follow-up. Two modes of the new matcher agreeing is not an oracle. Preserve full rasters and the admitted 256-note control. No second production dispatcher.
2. **Compile the region at hit packing, not at input.** Use the existing Project/pack emitters, including [inline continuations](../native/emerge_skia/src/tree/paint/inline.rs) and [Nearby bands](../native/emerge_skia/src/tree/paint/bands.rs). Intersect ordinary rectangular clips into one rect. For a turned box compile its oriented edges; for rounded/intersected shapes compile the edge and curved-corner tests in one coordinate space, with no links to clip or transform records. Store uncommon shape data in immutable typed spans, not the largest shape inline in every entry. Keep disjoint fragments disjoint and at their own paint positions. An enclosing box can reject early, but cannot confirm a nonrectangular hit. Match fractional points analytically: no pixel masks, draw snapping, shadow or image bleed. Preserve positive-area rectangles with inclusive edges, the viewport's exclusive right/bottom edge, rounding in the establishing space, and existing singular/nonfinite pose behavior. A simplified shape that cannot be proved equivalent uses the exact prepared form, not its bounding box.
3. **Separate hit geometry from event binding.** Replace `Option<Hit>` in Compose/Project with minimal hit facts, and hit-side `Scope`, clip chains and traversal pseudo-listeners with region entries and structural order spans. The plain rectangle needs just the rect and a compact listener/target selector. Measure its stride *and* its side data. Matching must not allocate. Do not recover the local origin from the clipped shape: clipping the left 10 px of a row does not turn a click at local x=12 into x=2. Convert coordinates only for a recipient or a gesture that needs to save a start point, never for every candidate. For hover, share a link to the nearest contributing hover ancestor; expand the selected path only, using each recipient's own map. Do not copy a hover stack into every child or confuse a fragment change within one mount with a new enter. Capture looks up the attachment and checks its capabilities in the installed frame without a fresh point hit; removal/remount invalidates it even with the same numeric ID. Keep this on the existing [`HitFrame` → dispatch](../native/emerge_skia/src/session/dispatch.rs) path.
4. **Compress repeated listeners without changing priority.** Encode a proven contiguous sequence as `Run(region selector, shared rule, member bindings)`. For monotone rows with disjoint interiors, binary-search their **actual settled intervals**, then test the candidate's exact shape, including cross-axis bounds. Field Notes alternates 32/48 px heights, has 4 px gaps and rounded corners: a gap or clipped corner is not a note hit. If two intervals share an edge, test both frontmost first; the first one's rounded corner can miss. Use the installed ordinal-to-attachment binding, never `base_id + row`. Split at intervening blockers, flags, nested shells, pass/placement changes or interleaved fragments; never sort by handler. For overlaps or unproved ordering, use exact scalar entries in that same array. Sharing a rule doesn't require sharing regions or eliminating the per-member identity data.
5. **Keep the array logical, not recopied on scroll.** Back it with immutable ordered chunks and the [existing selected ranges and bindings](retained-scroll-composition.md). For a moving run, first test its prepared stationary region. If inside, convert the point once at the run boundary and match the retained member regions in content coordinates. Never bake the first screen's intersection into a reusable row. Nested spans apply their own prepared boundary; no candidate walks paint ancestors, inverts a matrix or queries live layout. Translation updates the port binding/selection, not every row. A row-owned flag moves; a port-owned pin stays put. Reuse the existing worksets: a keyed move changes order/placement, a geometry edit changes affected regions, a change in point-pass participation updates hit bindings without repainting, and a change confined to a key matcher or soft-key action updates its descriptor, not its shape. Refresh navigation if focus eligibility changes. Replacing only the application message changes the route, not geometry. Pin all inputs in the sealed frame. Failed or held handoff keeps the old shape, identities, scroll receipts and route together.
6. **Replace the reservation, not just `sizeof(Hit)`.** Derive one `HitDemand` on the existing final-topology proof for both [live](../native/emerge_skia/src/tree/wire/publisher.rs) and [detached](../native/emerge_skia/src/tree/wire/patch.rs) admission. Count active target sites, blockers, ports/chrome and order breaks. For an inline wrapper and source both listening, allow two entries per possible line, bounded by their declared word slots. Bound exact shape pieces per contributing fragment by its own edges/corners and applicable ancestor guards. Include target bindings and capture lookup. Count a shared shape once per fragment, not once per mouse phase; price its pass rule and any member operands. As ports are enabled, bound hover links and active-path scratch, ordered key bindings/route bytes and virtual-key spec bytes by their actual contributors. Bound active contact/held-key state separately (two contacts can hold the same key). Do not preallocate a descriptor or timer per passive row. Reprice flat builder/readers, compiler scratch, frozen blocks, order/binding nodes, rounded capacities, whole pinned blocks and replacement overlap in [recording admission](../native/emerge_skia/src/tree/paint/recording/admission.rs). Replace hit-side `Pages<Hit,4>` and per-owner `Stock<Hits>` with packed blocks of those contributors; do not leave the old reserves behind or merely reduce their credits. Use checked byte arithmetic and fund the **uncompressed contributing sites** wherever grouping depends on later layout. Cover every offset, resize and scale without solving layout in the publisher. If the exact bound cannot fit, refuse before acceptance; `:busy` queues nothing, and an exhausted reader bank backpressures seal until release. No higher limits or fewer readers.

## Cutover gates

- **Geometry and order:** differential grids plus points on and either side of edges, tilted postcard corners, nested rounded clips, fractional scales, zero opacity versus zero zoom, paragraph gaps, behind/front/escaping blockers and scrollbar track versus content. Compare both winners and local payloads. Run the same cases with grouping on/off in tests. Keep [Nearby](../test/emerge_skia/nearby_layers_test.exs) and [transform](../test/emerge_skia/static_transforms_test.exs) fixtures intact.
- **Identity and lifetime:** repeat identical callbacks, then distinct row messages using the same rule; reorder, edit actions/messages at equal bounds, remove/remount the winning ID mid-gesture, and hold disjoint frames across jumps and failed handoffs. Check click/press, captured drag, swipe endpoints, nested wheel axes, Tab/reveal and raw touch with the [installed input](../test/emerge_skia/scroll_inputs_test.exs) and [route epoch](../test/emerge/viewport_submit_routes_test.exs) tests. Preserve absolute scroll serials and axis epochs.
- **Split dispatch:** assert the complete ordered trace, including no extra callbacks or raw events. Cover child/parent hover across a sibling, stationary installs and window exit; down on A/up on B versus up/click/press on A; [capture](../test/emerge/pointer_drag_test.exs) across scale, outside release and remount. For the remaining ports require reference traces now and end-to-end parity when each lands: overlapping exact/all key matchers, down/up/completed press and focus loss; text/slider changes versus echoes; soft-key tap/hold/repeat, slide-off and two independent contacts. Include blocked overlays and held route epochs. Check the [binding registry](../test/emerge/diff_state_test.exs) and the [actual mailbox](../test/emerge/viewport_test.exs), including external PIDs and custom wrapping. Do not weaken currently failing mixed fixtures or silently accept unsupported declarations.
- **Cost:** multiple positional handlers on one member's same fragment must not duplicate its region. Extra focused key bindings or a value callback on an already participating control add **zero spatial entries**; report their descriptor bytes separately. Adding 20,000 ordinary passive leaves without new blockers/ports must add **zero listener slots**. A homogeneous eligible row run uses **one rule** and a bounded interval lookup, not 20,000 programs; report member bindings and exceptions separately. On tripled Cards 30 → 31 px retain one Project job for the port, zero descendant assembly and zero hit payload writes; returning to a valid recording must not rewrite it. Measure membership probes, winner conversions and first-hit/last-hit/miss timing separately from compilation. On both ingress paths test exact-fit, one-over, pinned replacements and release/retry with no unfunded growth.
- **Report before removing the old test oracle.** Repeat the 256/20k, 0%/80% profiles: compare credits, actual cold backing **including every replacement table**, and issued bytes separately. Require a net reduction, not a shift into per-key metadata or slower input scans. Keep one detached/five live readers and logical v25 diagnostics. Run locked `cargo test` and `mix test` against the named baseline failures/exclusions, plus ordinary binary-headless and private Wayland input checks. No new NIF, EMRG tag, public flag or widget. A successful 20k install is **not** claimed or implied: the independent non-hit workspace limit and [bounded recording residency](scroll-recording-residency.md) are separate work.
