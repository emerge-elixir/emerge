# Retained renderer stats logs

**Implemented.** `diagnostics: [logs: [:stats]]` now emits the native multiline `renderer_stats` report on retained Wayland and binary headless, using the same option, log target, info level and approximately five-second interval as `../emerge_demo` on `main`. The adjacent Wayland Cards gallery uses this option instead of an Elixir process polling submission time. `stats: true` alone collects silently. The report takes the same window as `EmergeSkia.stats(renderer, :take)`; `:peek` leaves it intact. The v25 snapshot shape has not changed.

## What is measured

| Report rows | Boundary |
| --- | --- |
| Frames, fps, display mode / target cadence | Successful backend handoffs over the elapsed window. FPS includes idle time; it is not the throughput limit. The Wayland output mode, when reported, is distinct from a headless frame cap. |
| Edit decode, prepare, apply; patch tree actor | For each accepted publication consumed by the tree: summed nonempty wire-slice parsing, provisioner's stream finish and preparation, summed apply slices, and installation of the accepted declaration **on the tree actor**. No admission wait or rejected edit is counted as a successful publication. |
| Pipeline submit→tree, tree, render queue | Native acceptance to consumption of each edit; the worker turn that actually sealed a scene; time from sealing/queueing that scene to its draw worker starting. Several edits can contribute to one scene. Layout and refresh time the calls to update retained layout/paint preparation and collect output, including retries. They are not layout-job counts. |
| Render, draw, flush, GPU flush, submit | Successful producer turn including target acquisition/preparation or reuse. Draw times CPU rasterization or GPU command recording. GPU `render flush` times device finish, including the explicit Skia flush and submit calls. On GL, obtaining the readable texture also happens inside finish, **before** the separately timed flush. A reused target has no invented draw/flush samples. |
| Present submit, submit→handoff, frame callback | Time in the successful binary send, shm commit/flush, or GPU presenter handoff. For an edit-bearing scene the longer span starts at its earliest folded native acceptance, **not** at input or BEAM render. A Wayland callback must match the successful handoff; rejected, reconfigured or early feedback is not substituted. A callback is not presentation feedback or scanout. |
| Event resolve | Dispatch of an input event against the installed scene. Does not time downstream application handling. |
| Layout cache, scene pipeline, renderer cache, asset memory | Live frame/glyph-run/composition entries and commands/glyph IDs/hits at the last seal, scenes constructed, pending commands replaced by a newly offered scene, and reused drawing targets. Queue overwrites do not count every reason a scene may never be handed off. Renderer-local sized-source, bitmap and SVG picture accounting is read without inventorying or retaining assets. Gauges are not per-window work counts or total process/GPU memory. |

Timings show average/minimum/maximum in milliseconds and sample count. They overlap; don't add them as stages of an end-to-end latency. Idle windows say `no samples`; inapplicable stages say `unavailable`. No legacy cache hits, video/DRM statistics or GPU timer queries are synthesized. No extra renderer thread, redraw, device synchronization, wire format or NIF was added. A render or handoff of at least 4 ms may emit `renderer_slow_frame`, at most once per stage per second per logging session.

## Verification

- The [public diagnostics tests](../test/emerge_skia/diagnostics_test.exs) check disabled and silent collection, two headless submissions with one actual raster draw after a listener-only edit, input, peek/take/reset, redirecting the log target and a second (idle) window without a frame. [Native controls](../native/emerge_skia/src/session/stats/tests.rs) cover interval math, persistent gauges and slow-log gating; the [callback control](../native/emerge_skia/src/session/stats/callback.rs) delivers the device report after the callback and rejects a mismatched generation or early timestamp. The asset gauge test distinguishes an evicted but still live bitmap from cached bytes.
- Private 720×600 Wayland output at 60 Hz: both the default Vulkan gallery and explicit OpenGL gallery received 18 routed clicks and passed 19 installed-capture/compositor comparisons. Each printed **23 handoffs**, 19 accepted edits and 22 matched handoff→callback samples, then **0 handoffs** in the idle window. Both summaries reached Elixir Logger. A separate direct `wl_shm` window checked changed, reused and changed pixels followed by idle, without claiming a submit on target reuse. This is not a GPU benchmark or a physical scanout test.
- Locked Linux Rust tests: 339 default, 339 on Rust 1.91, 333 without default features, 363 with both Wayland GPU APIs. Stage-probes: 339 native and 20 headless stage tests. Strict Clippy, formatting, warning-clean Mix compilation, Credo, Dialyzer and ExDoc checked. Cards: 11/11. Emerge: 4/4 diagnostics and 112/112 focused regressions; ordinary seed 17 **916/959**, the same 43 failures and 21 exclusions by name as the [scroll checkpoint](scroll-paint-visibility.md#linux-qualification).

Machine-local receipts and replay: `/workspace/.emerge-full-stats-xMX1sf/HOWTO.md`. Changes are relative to its `before.lib` and `before.app` in the already-dirty renderer and consumer, not to clean HEAD.
