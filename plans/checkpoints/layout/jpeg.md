# Logical JPEGs in `image/2`

**Complete for `.jpg` and `.jpeg`** (case-insensitive logical strings and `~m` references under the renderer's application `priv/`). The before arm is the qualified [logical PNG implementation](raster-images.md), **not** the `3e964e7` binary. It refused the public JPEG upload with `renderer_upload failed: expected a relative logical PNG name`. Reference: `main` `aef5e42fc789c396505f85c34810b2ca9c008586`. Each producer used its own verified mapped NIF.

The [loader](../../../native/emerge_skia/src/raster_assets.rs) opens one regular file through the same directory handle, without following symlink descendants. The [format check](../../../native/emerge_skia/src/raster_assets/format.rs) selects the allowed decoder by extension and requires a complete primary JPEG, skipping length-delimited segments and stuffed entropy bytes to find its end. A thumbnail's end marker is not the primary image's; trailing data after a complete image is allowed. Skia must return success, not partial pixels. The existing caps still apply: 64 MiB each for encoded file and decoded bitmap, 32,768 per axis, 256 MiB resident decoded pixels per loader. The codec also gets a working-memory limit. These are not total-process limits.

EXIF orientation is applied **once on the worker**, with both raw and display bitmap storage budgeted for a non-identity transform. A ready binding contains one immutable display-oriented bitmap; it supplies both pixels and intrinsic dimensions. No new public API, wire field, tree pass, draw command, cache or filesystem access during replay. A bad declaration still refuses atomically; a valid name that cannot be opened or decoded settles to the failed-image indicator. [Sizing, fit, opacity and submission](raster-images.md) are shared with PNGs. At this checkpoint both formats decoded at full resolution. The subsequent [fitted decode port](sized-rasters.md) preserves this behavior when the option is disabled.
