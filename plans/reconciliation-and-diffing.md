# Reduce the cost of producing a tree patch

**Implementation and [measurement checkpoint](checkpoints/performance/snapshot-diff.md), not an API port.** The comparison is against the existing Elixir producer at retained `ffa22073c663f61b7dda59c11f0ca8af67422abc`. Keep existing public calls, EMRG v10 bytes, route edits and the native renderer unchanged. The [viewport](../lib/emerge/runtime/viewport.ex) still hands the producer a complete declaration. A key identifies an occurrence, not whether its label or callback changed. For independently rebuilt trees, accept that finding the diff can take a linear walk; reduce the bookkeeping, copying and garbage collection during that walk.

**Out of scope:** splitting a view into static structure and dynamic regions bound to state keys or controller outputs. That belongs to the viewport’s data-source design, not the snapshot reconciler. No dependency tracking or row-local rendering prototype in this plan.

## Why start here?

In the [one-label investigation](checkpoints/performance/list-label-delivery.md), the 500-row edit reached prepared native output in **0.038 ms** at 960×640. Yet the assigned producer visited **1,002 nodes** for a **113-byte** forward patch. It allocated **278,023 traced heap words/edit** (binary-only: **263,998**); `claim/3` accounted for 75,774 and `close/7` for 66,427. These are allocation counts, not function timings. In the default-heap GC probe, collections explained 0.607 ms of the 0.809 ms excess over `main`. The historical end-to-end slowdown did **not** reliably repeat; reducing that one frame median is not the acceptance test.

Two other cases prevent overfitting: reversing the 500 keys cost **1.81 ms** on the retained binary producer, and changing inherited font alignment on the 100-card grid cost **2.42 ms** for a **70-byte** patch. [Shared-surface measurements](checkpoints/performance/shared-surface-baseline.md). `main` (`aef5e42`) is context, not the oracle for retained moves or patch bytes.

## Planned sequence (completed trials in the checkpoint)

1. **Freeze the comparison before editing.** In a new copy of the two benchmark bundles linked above, verify the manifests and replay `ffa2207` with its mapped v10 NIF. Save forward/undo bytes, assigned trees, occurrence IDs, branch/site stamps, registry and routed deltas for identical histories. Time [assigned, binary-only and routed updates](../lib/emerge/engine/diff_state.ex) separately. Include cold full encode, rebuilt-but-equal no-op, one label, callback-payload-only, listener add/remove, reverse, insert/delete and inherited font. Exercise shared and independently rebuilt declarations. Keep unsupported Nearby/scroll examples as **producer** tests, not native timing wins.

   As a scaling control, edit the last label in lists of 50, 500 and 5,000 rows. Count nodes visited and sibling entries read or copied; measure declaration construction separately. Fewer allocated words per visit is a useful result, not evidence of a sublinear diff.

2. **Reduce duplicate bookkeeping in [`claim/3`](../lib/emerge/engine/reconcile.ex).** At the baseline every occurrence wrote `claims`; every keyed one also wrote `seen_keys[key] = id`. Trial using that exact key→ID entry to answer “was this old keyed occurrence claimed?” in displacement and retirement. Match only against the **old** declaration: key+kind globally, or kind at the unkeyed ordinal under a matched parent. The **new** seen map detects duplicate keys and resolves forward targets; absence ends identity. Check the *ID*, not just key presence: replacing a key with a different kind must retire the old ID and its callback. Keep explicit ID claims for unkeyed occurrences and detached `Patch.diff/2` imports, where differently keyed supplied nodes can claim the same ID. Do not delete an ownership check without proving its replacement. Measure this change alone; keep the simpler existing path if the saving is negligible.

3. **Avoid constructing results that `close/7` and the [child fold](../lib/emerge/engine/reconcile/children.ex) throw away.** First test a stable-node return *after* children and pending forward references settle but *before* building replacement VNodes/stamps. Require exact resolved attrs (including callback changes), owner, site, order and child stability; a matching branch stamp alone does not suffice. Then, as a separate trial, return the old VNode list when every child is stable; on divergence copy a necessary prefix at most once, never index into the list. Empty new children against nonempty old children still retire the old tail. Build the public assigned `Element` when requested, preserving non-wire fields such as `frame`; binary/routed modes must still return no assigned tree, including on mixed-mode update chains. No full-tree equality scan, second child order or cache of prior generations.

4. **Re-profile before widening the work.** Choose at most one remaining cost. For the inherited-font case, count real versus unchanged [`Labels.bind/3`](../lib/emerge/engine/reconcile/labels.ex) results before changing pool writes; real descendant site changes must remain visible even with closed wire edges. Keep exact descriptor equality, collision/exhaustion checks and retirement after all claims. For a wide reorder or two changed siblings, count temporary ancestor bodies/edge lists discarded when a single child patch suffices. Materialize wire edges only where needed for the final enclosing replacement; preserve exact records when a second change does require that ancestor. Only tune [`Patch.encode/1`](../lib/emerge/engine/patch.ex) if encoding itself measures hot. Use linear list cursors, prepend/reverse and iodata per the [BEAM constraints](../guides/internals/beam-performance-constraints.md). No heap-setting workaround, ETS, new opcode, dirty-hint API or second producer.

## Gates for each trial

- **Diff correctness:** Replay fixed fixtures and seeded edit/undo histories in each mode against the frozen v10 producer from the same starting state, and independently expand the sparse patch against its predecessor as in the [identity tests](../test/emerge/stable_identity_test.exs). Check exact bytes/target/record order, assigned fields, next ID, key/node indexes, stamps, full registry and routed additions/deletions (compare logical callback roles across VMs). Include separately edited siblings; equal-looking keyed swaps; unkeyed ordinals; cross-parent moves in both traversal orders; promotion/demotion; key reuse after absence or kind change; ordinary↔Nearby; duplicate keys/IDs and mixed siblings; forward scroll targets disappearing and returning. A refusal must leave the old state usable for the next valid edit. Check mount, `<<>>`, clear to `nil`, live `none()`, bare kept ID and both independent `:same` fields. Callback-payload-only means **empty tree bytes but a nonempty route edit**.
- **Renderer contract:** Preserve [D1–D5](../guides/internals/retained-decisions.md): accept edits → invalidate once against the final tree → recompute. For supported cases compare whole submitted RGBA frames on edit/undo to fresh renders. Check raw press/release and routed callback/local coordinates across a held keyed move; with A visible, B sealed and C accepted, B’s success must install B’s routes, and B’s failure must leave A’s. No window claim from headless frames. Run focused identity, diff, patch, scroll and [route publication](../test/emerge/viewport_submit_routes_test.exs) tests, then `cargo test` and `mix test` under the [shared lock](../scripts/performance-lock.sh) with an immutable source ID. Compare **named** failures/exclusions to `ffa2207` (766/859 passed, 93 failures, 21 exclusions); no new ones.
- **Performance decision:** Compare each trial to its immediate baseline and the final candidate to `ffa2207`. Use eight alternating fresh VM pairs, exclusive lock, CPU 8, one Rayon worker, same BEAM settings and verified BEAM/NIF identities. On ordinary caller heaps, report untraced producer medians and paired 95% intervals. Separately record attributed words, GC overlap, reachable `DiffState` words and live index/label counts after repeated churn and clear. No profiling in the timing runs. Keep native first/changed/clean refresh, pre-encoded patch→frame, public assigned call→frame and actual viewport rerender→frame as separate controls; never subtract them.

**Proposed snapshot-diff target:** ≥20% fewer traced words on the label edit in **both** assigned and binary modes, plus a lower untraced assigned-producer time (paired interval below zero). Protect binary/routed updates, full encode, reorder, inherited font and actual viewport delivery: use +5% as the upper non-regression margin on paired time; a wide interval is inconclusive, not a pass. Do not trade temporary words for a larger retained state or growing indexes. Record each trial's before/after, guards, and keep/revert decision; stop when the target is met or the next change lacks evidence.

**Outcome:** the selected producer met the snapshot-diff target and the specified producer and actual viewport guards. This is not a blanket delivery win: the standalone public fill-weight edit regressed even though the actual fill-weight viewport improved. See the [results and qualification](checkpoints/performance/snapshot-diff.md).
